# Changelog

What each commit delivered, newest first. Design decisions and their reasons are in the [design doc's decision log](docs/design.md#critique-and-key-decisions); the roadmap's Phase 0 checklist is in [Build roadmap](docs/design.md#build-roadmap).

## Unreleased

**Fewer tokens per run, and rate limits waited out**

- A rate limit is now waited out as often as it recurs, while each suggested wait is 30 s or less and one call's waits add up to a minute at most; before, two retries per call, and runs on Groq's free tier failed with 2 s left to wait.
- Shot and substitution lines in every timeline prompt are cut to who and how (`Víctor Muñoz, shot, saved by Caoimhín Kelleher`); goals, cards, VAR and woodwork keep the source's words.
- The fact-sheet call (prompt v2) gets only the shots near the moment and its beats; the rest become one line of attempts per side, on target, and who shot most.
- Together: input per run on the recorded week down from about 8,400 tokens to about 6,600 (Pick the moment −32%, Build the fact sheet −40%).
- The production stack keeps the analysis cache on, in its own volume: a repeat run of a week, or a retell, makes only the poem and judge calls.

**Fixes: schema rejections and the production healthcheck**

- A structured reply the provider rejects against the schema itself (Groq's `json_validate_failed`, seen from GPT-OSS 120B on Build the fact sheet) now gets the same one retry as a reply that does not parse, instead of ending the run as a provider error.
- The production backend's healthcheck is `python -m app.healthcheck`: Podman split the old one-line `python -c` check on its spaces, so the container always showed as unhealthy while serving normally.

**Production compose**

- `compose.prod.yaml` (`make prod`, `make prod-down`, `make prod-logs`) runs the stack for a server behind a tunnel or reverse proxy: the distroless MCP server, and the backend's runtime image, which now includes the built UI and serves it at `/` next to `/ws` on one origin. Only the backend publishes a port, on `127.0.0.1:${APP_PORT:-8080}`; no source mounts, no reload, no server LLM key, `restart: always`.
- The socket accepts only the page origins in `ALLOWED_ORIGINS` (required in production; empty allows any, for development), so another site cannot open it from a visitor's browser.
- `deploy.sh` deploys or redeploys on the server without make: it pulls, rebuilds, restarts, waits for `/healthz`, prunes the old images, and warns if the dev stack is still running or the stack would not survive a reboot.
- The backend image builds from the repo root, as the frontend's does; the frontend image's `build` stage is gone, since the backend image builds the bundle.

**Fixes: event ids and the analysis cache**

- A bare number from the model (`92` for `e92`, seen from GPT-OSS 120B) is read as its short event id, instead of failing Pick the moment.
- The development analysis cache keeps only answers the pipeline accepts, and skips a cached answer it would reject; before, one bad moment failed every later run of that week and model at once. The checks live in `app/pipeline/answers.py`, shared by the pipeline and the cache.

**Plain `docker compose up`**

- `docker compose up -d` (or `podman compose up -d`) runs the whole stack, with no `.env` and no make. A one-shot `mcp-token` service writes a random shared token into a volume, and the backend and MCP server read it through the new `MCP_AUTH_TOKEN_FILE`; an `MCP_AUTH_TOKEN` set in `.env` still wins.
- `make dev` no longer creates `.env`; `make .env` copies the template for editing.

**The logo**

- A chip with a football pitch on its die, between typographic quotation marks drawn in the chip's character: AI, about football, saying something. It replaces the placeholder crosshair in the header, the Angular favicon and the README.
- Generated by `docs/brand/make_logo.py` (`make brand`): the mark, the favicon (SVG, green in light and dark tabs, with `.ico` and Apple touch icon fallbacks), the header's inline SVG, and a macOS-style app icon for the portfolio (the green mark, large, on a vertical dark-grey gradient tile). The chip is sized so it always sits a fixed gap (the pin weight) from the quotes.
- The header title is trimmed to its cap height (`text-box`), so its capitals and baseline line up with the chip's top and bottom edges; browsers without `text-box` get a measured offset.

**Guardrails** (Phase 0)

- Every poem goes through seven checks before it is shown: score, names, quotes, originality, length and form, and grounding, run for real; safety (moderation) shows as skipped until Phase 1. Code in `backend/app/guardrails/`.
- A failing poem gets one rewrite with the problems listed (`repair_poem.v1.md`); if it fails again, the run ends with `guardrail_failed` and the report, and nothing is shown.
- The name check is a deterministic capitalised-word check against the roster, the facts' names, club nicknames and grounds, the venue and the form's stock figures. A named-entity model is future scope ([TODO.md](TODO.md)).
- The 8 hand-written sample poems are the checks' false-alarm test: all must pass.
- The mock LLM now writes poems that pass every check in all 8 forms, so keyless runs still end in a result.
- README: guardrail thresholds and their reasoning.

**Fewer LLM calls and tokens**

- A development cache of the pick, moment and fact draft (`ANALYSIS_CACHE_DIR`, on a compose volume): running a week again with the same model makes 2 LLM calls instead of about 7, and the poem is still written fresh.
- The grounding judge runs only when the deterministic checks pass, saving a call on every poem that needs a rewrite.
- Prompts name events by short ids (`e12`) instead of source refs, saving around 400 tokens per timeline; ids are mapped back before the pipeline sees them.
